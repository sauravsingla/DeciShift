# Concepts

## Decision change as the unit of analysis

DeciShift starts from an operational question: after a version change, which historical final decisions differ? It then works backward through a structured pipeline to quantify which changed software components contribute under controlled hybrid executions.

## Observed difference vs attribution vs causality

An observed flip is directly measured by replaying the same historical record through two pipeline versions. Component attribution is generated by replacing selected software components with their candidate versions while holding other components at baseline. Neither statement alone identifies a real-world causal effect on people, systems, or outcomes outside the replayed software.

## Score and decision attribution

Score attribution decomposes the candidate-minus-baseline calibrated-score difference. Decision attribution decomposes the candidate-minus-baseline binary final decision. Components such as thresholds and deterministic rules can have zero score contribution but non-zero decision contribution.

## Interactions

Pairwise interactions in v0.1 are baseline-anchored second-order differences. An interaction-only flip occurs when neither component alone changes the baseline decision but both together do.
